# MES: Пищевое производство

Фронтенд-демонстрация MES на React и Vite. Серверной логики и сетевого API нет. НСИ, производственные данные и история хранятся в IndexedDB браузера. Данные старых сохранений localStorage переносятся при первом открытии сценария. Шрифт поставляется локально.

Доступны два независимых демо: «АГРОЭКО-ЮГ» и «Молочное производство». Сброс в настройках действует на выбранное демо.

## Запуск

```sh
npm install
npm run dev
```

```sh
npm test
npm run build
```

## НСИ

Во вкладке «Поставщики и потребители» ведётся единый справочник контрагентов: код, наименование, роли и доступность для новых документов. Одна организация может иметь обе роли. Доступны поиск, фильтр роли и показ недействующих записей. В приёмке выбирается поставщик, в отгрузке — потребитель; нового контрагента можно добавить и сразу выбрать непосредственно в форме. Произвольное текстовое имя вместо записи справочника не принимается. Недействующие контрагенты не участвуют в новых документах.

При загрузке старого сохранения справочник заполняется существующими поставщиками и получателями без повторов. Приёмки и отгрузки хранят ссылку на контрагента и снимок его наименования: последующее переименование или отключение не изменяет историю документов. Данные справочника сохраняются отдельно для каждого демо.

Все новые ручные действия, списания, результаты производственных операций и ОТК используют текущего пользователя из шапки приложения — Илью Аладьева. Ошибочное имя демосотрудника ОТК в старых результатах, списаниях и событиях исправляется при загрузке. Карточка выполняемой операции показывает конкретное рабочее место; полный путь иерархии и повтор имени исполнителя внизу формы убраны. Исполнитель сохраняется в результатах и журнале.

В разделе НСИ доступны справочники процессов, материалов и структура производства. Кнопка «Редактировать» в списке процессов открывает самостоятельное окно редактора. По умолчанию отображается список операций с общей панелью «Добавить», «Редактировать», «Удалить», «Порядок операций». Для редактирования или удаления нужно выбрать строку. Форма операции открывается отдельным режимом с вкладками «Основное», «Материалы», «Параметры», кнопками «Сохранить операцию» и «Отмена». Ввод не изменяет маршрут до сохранения операции; отмена отбрасывает только локальные изменения формы. Поля проверяются при сохранении, а общий материальный баланс маршрута — при публикации процесса.

Порядок меняется в отдельном режиме: строки можно перетаскивать за маркер или задавать позицию через список, в том числе с клавиатуры. «Применить порядок» переносит последовательность в маршрут, «Отмена» сохраняет прежнюю последовательность. Свойства процесса вынесены на отдельную вкладку. Сохранение черновика и публикация процесса закреплены внизу списка; в режиме операции доступны только действия этой формы. При закрытии с неприменёнными изменениями появляется подтверждение. Ввод в незавершённой форме также учитывается защитой от перезагрузки страницы.

Схема взаимодействия следует [DWP Add another thing](https://design-system.dwp.gov.uk/patterns/add-another-thing/how-it-works) и рекомендациям [Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines): список, явные действия с выбранным элементом, отдельная форма, подтверждение удаления.

Каждая операция содержит:

- Тип: производственная операция или контроль качества. Контроль может стоять в любом месте маршрута.
- Класс оборудования для назначения рабочей единицы своей линии, конкретный ресурс либо исполнение без оборудования.
- Потребляемые материалы: складские партии или выпуск предыдущих операций этого заказа.
- Выпускаемые материалы: передача следующим операциям либо выпуск на склад после завершения процесса. Поддерживаются несколько выходов и побочная продукция.
- Произвольные параметры: число с единицей измерения, допусками и номиналом, текст, подтверждение. Можно включить обязательность и пересчёт числового параметра на объём заказа.

Процесс сохраняется в черновик и публикуется после проверки ссылок, допусков и обеспеченности внутренних материальных потоков. Во время редактирования опубликованная версия остаётся доступна для новых заказов. Публикация изменений создаёт следующую версию. Заказы получают независимый снимок процесса при создании; новые редакции НСИ не меняют их маршрут, нормы и историю. Архивный процесс недоступен для новых заказов, существующие заказы продолжают исполняться.

Единицу измерения материала, который уже используется в опубликованном процессе или учёте, изменить нельзя. Недоступное оборудование нельзя назначить в публикуемом процессе; оборудование активного заказа нельзя отключить.

## Структура производства и занятость

Рабочее место оператора содержит очередь отдельных производственных операций. Фильтры линии и оборудования берутся из структуры предприятия. При открытии очереди выбраны все линии и все рабочие места. Последующие операции появляются после выполнения предыдущей. Каждая операция запускается отдельно, может быть приостановлена с причиной, возобновлена и завершена. История сохраняет время запуска, завершения и интервалы пауз. Контроль качества вынесен в свой раздел и также запускается отдельно. Маршруты последовательные; параллельные ветви не моделируются. Старые активные сохранения продолжают выполняться без повторного списания материалов.

В готовой продукции показываются данные выпуска, остаток, срок годности и статус партии. Условные текстовые места хранения удалены из этого экрана и из формирования нового выпуска: справочника складских ячеек и операций размещения в приложении нет. Складские адреса требуют самостоятельной модели учёта; узлы производственного оборудования её не заменяют.

Применена иерархия ролей оборудования по ISA-95: предприятие → площадка → участок → рабочий центр (линия) → рабочая единица (оборудование). Это выбранная модель для демонстрации, а не заявление о сертификации приложения. Основание: [ISA-95 Common Object Model, OPC Foundation](https://reference.opcfoundation.org/specs/OPC-10030/7.4.1).

Узлы создаются и редактируются в НСИ → Структура производства. Можно добавлять площадки, участки, линии и оборудование, задавать родителя и доступность. Оборудование под линией доступно только этой линии; оборудование непосредственно под участком является общим ресурсом линий этого участка. Класс задаётся в карточке оборудования. Циклы, неправильные уровни родителей, удаление используемых узлов, перенос оборудования незавершённых заказов и отключение занятых узлов блокируются.

В процессе указывается класс ресурса. При создании заказа он разрешается в конкретную рабочую единицу своей линии; если их несколько, выбирается первая по коду, с приоритетом оборудования линии над общим оборудованием участка. Форма заказа показывает назначения. Несовместимая линия недоступна для выбора. Назначения сохраняются в снимке заказа, вместе с маршрутом и нормами.

Линия эксклюзивно закреплена за заказом до окончания его производственных операций, включая ожидание и промежуточный контроль. Финальный контроль без последующих производственных операций освобождает линию; его собственное оборудование, если назначено, остаётся занятым. Ресурс занят только текущей выполняемой или приостановленной операцией. Отдельные линии не конфликтуют, если у них разные рабочие единицы.

После завершения операции следующий шаг ожидает отдельного запуска. Если следующий ресурс занят, завершённая операция сохраняется, заказ переходит в «Ожидание ресурса». Следующая операция не занимает оборудование до команды оператора «Запустить операцию». Сам запуск складские материалы не списывает. В интерфейсе видны причина ожидания, блокирующий заказ и его линия. После освобождения ресурса можно продолжить без повторного выполнения предыдущей операции.

## Сквозной сценарий

1. Создать материалы и оборудование, настроить процесс и опубликовать его.
2. Создать заказ по опубликованной версии. В карточке при необходимости выбрать MTU и количество резерва для каждой операции. Все поля резерва необязательны. Нажать «Подготовить заказ». Список доступных MTU упорядочен по сроку годности; просроченные, недопущенные и заблокированные партии исключены.
3. В рабочем месте оператора открыть доступную операцию и нажать «Запустить операцию». В разделе «Списание сырья» ввести или отсканировать MTU, указать фактическое количество и нажать «Списать сырьё». Это необходимо и при наличии резерва. Допустимы частичные списания и несколько MTU на один материал. Другую MTU вместо зарезервированной можно подать с явным подтверждением замены резерва. Потребление внутренних полуфабрикатов из предыдущих операций фиксируется при запуске операции.
4. Выполнить операции с настроенными атрибутами и фактическим выпуском. Контроли качества отображаются также в отдельном разделе качества. Неподтверждённое потребление сырья, отклонения от допусков и незаполненные обязательные поля блокируют завершение.
5. После последней операции появляются складские партии всех настроенных выходов. Их можно отгрузить или зарезервировать на вход следующего процесса. Зарезервированный остаток недоступен для отгрузки.
6. Генеалогия показывает источники, фактическое потребление и резервы, результаты операций, выпуски и отгрузки. Выпуск предыдущего заказа раскрывается как источник следующего.
7. Блокировка исходного сырья запрещает дальнейшее потребление и отгрузки связанных партий, включая цепочки нескольких заказов.

В операциях с материальным балансом оператор вводит фактический выпуск каждого выхода. Потери рассчитываются как разность входа и выходов, рядом отображаются норма и отклонение. Кнопка «Заполнить по плану» явно переносит плановые значения в поля факта. Межоперационные массы передаются по факту, включая распределение между последующими потребителями одного полуфабриката.

До резервирования в карточке заказа можно изменить план выпуска. Здесь отображаются свободные остатки и нехватка, доступен пересчёт по остаткам с учётом шага фасовки. Для отдельной туши предусмотрен пересчёт по её фактической массе. При загрузке старого демо АГРОЭКО уточняются исходные нормы и ещё не запущенные стандартные заказы обвалки. Выполненные операции и учтённые партии сохраняют свои фактические значения.

Начальные данные молочного демо: смена 22.10.2026, восемь заказов, три линии, три редактируемых процесса, тринадцать материалов и пятнадцать единиц оборудования (по пять на каждой линии). ПЗ-2610-004 и ПЗ-2610-005 используют разные смесители и могут исполняться параллельно. Начальные записи задаются в `src/catalog.js`, общие правила исполнения находятся в `src/domain.js`, правила иерархии и выбора ресурсов — в `src/resources.js`. Количество операций, параметры и материальные нормы в движке не зафиксированы.

Сохранения версий 1 и 2 автоматически переносятся в модель версии 3. Для пяти исходных ресурсов создаются отдельные рабочие единицы каждой линии, требования процессов переводятся на классы, назначения существующих заказов привязываются к их линиям. Добавленное пользователем оборудование сохраняется как общий ресурс участка. Остатки, резервы, отгрузки, результаты и пользовательские процессы сохраняются. При ошибке загрузки исходное сохранение не перезаписывается. Полный сброс доступен отдельно в настройках демо.

## Реестры и история

В группе «Производство» диспетчерская показывает состояние линий, отклонения и выполнение плана. Создание и подготовка заказов выполняются в реестре производственных заказов. Сырьё, межцеховые партии, готовая продукция и отгрузки находятся в группе «Склады и отгрузки». Журнал событий, генеалогия и производственные отчёты объединены в «Учёт и отчёты».

В «Готовой продукции» показываются партии с положительным остатком, включая полностью зарезервированные. После полной отгрузки партия исчезает из остатков; при частичной остаётся неотгруженное количество. История каждой отгрузки доступна в «Отгрузках», а исходная партия сохраняется для генеалогии.

Исторические реестры содержат поиск, период, постраничный вывод и дату со временем. Журнал хранит все новые события без ограничения в 150 записей. Отгрузка сохраняет наименование продукции, код партии, заказ, количество и получателя на момент выполнения. Снимок состояния сохраняется транзакцией IndexedDB перед подтверждением производственного действия.

Каждая учётная партия служит MTU. При приёмке можно указать отдельный код MTU. Резерв уменьшает свободный остаток, но не складской. Явное списание оператором уменьшает складской остаток и соответствующий резерв одной транзакцией. Проверяются материал операции, допуск, срок, доступный остаток с учётом чужих резервов, единица и потребность. Живок списывается всей партией с проверкой числа голов, туша — целиком с соответствием плановой массе. При другой массе туши план сначала пересчитывается в карточке заказа. В журнале, карточке и генеалогии резерв отделён от списания; идентификаторы фактически использованных MTU сохраняются в результатах операции. Повтор одной подтверждённой команды не создаёт второго списания. Старые сохранённые списания признаются фактом, повторно вводить их не требуется.

## Показ АГРОЭКО-ЮГ — до 60 минут

Показ проходит через штатные разделы. Новая пустая смена содержит восемь запланированных заказов. Для отдельного свежего показа можно сбросить только демо АГРОЭКО в настройках; это удалит его текущие данные. Для продолжения существующего показа сброс не нужен.

1. **НСИ → Справочники** (5 минут). Открыть опубликованные процессы: маршрут, нормы сырья и выходов, параметры и рабочие места. Заказы используют сохранённую версию процесса.
2. **Склады и отгрузки → Сырьё и материалы** (5 минут). «Приёмка»: СК Северный, 3 головы, фактическая живая масса 365 кг, по документам 370 кг, ТСДок ТС-041. Открыть принятую партию, показать расхождение и нажать «Допустить в ЗПС». Запомнить её код MTU.
3. **Производство → Производственные заказы → ПЗ-2610-001** (5 минут). Выбрать принятую MTU в необязательном резерве, «Подготовить заказ», «Открыть операцию». Показать, что резерв не уменьшил остаток. «Запустить операцию», ввести MTU и 365 кг, «Списать сырьё». «Заполнить по плану», подтвердить обработку партии убоя, «Завершить операцию». На выходе три отдельные туши по 100 кг и побочные потоки.
4. **Заказы 002–004** (15 минут). Для каждого зарезервировать свою тушу из заказа 001. Открыть и запустить «Идентификация и маркировка туши · КТ8». MTU из резерва уже выбрана. Нажать «Считать разногу» (имитация считывателя), затем «Подтвердить подачу и идентифицировать»: это одновременно подтверждает физическую тушу и списывает её целиком. Нажать «Получить данные AutoFom» — имитация первичной классификации. MES автоматически присвоит номер убоя; на чистом демо это УБ-26-000001, УБ-26-000002 и УБ-26-000003. Нажать «Скачать QR», сохранить SVG, затем отдельно «Подтвердить нанесение». Завершить операцию. Через «Карточка заказа → Открыть контроль → Начать контроль» провести ветосмотр: документ необязателен, допуск подтверждается явно, примечания сохраняются. Тушу заказа 003 направить на реинспекцию с причиной: номер убоя у неё уже есть. Для 002 и 004 подтвердить допуск, на КТ19 сверить полученную постность AutoFom, массу туши и ветеринарный допуск и нажать «Завершить операцию»; повторно вводить постность не требуется (категория присваивается только при наличии настроенного классификатора), затем охлаждение до 98,8 кг. Между операциями — отдельный запуск. После охлаждения номер туши и QR сохраняются.
5. **Заказ 005** (7 минут). Выбрать охлаждённую тушу с номером убоя УБ-26-000001, подготовить. Запустить разделку, считать QR туши или ввести её номер убоя и 98,8 кг, списать, заполнить выходы по плану, завершить. Перейти к обвалке и запустить её. Показать внутреннее потребление без повторного складского сканирования. «Заполнить по плану»: 64,4 кг мяса, 16 кг тримминга, 3,6 кг шпика, 13 кг кости и 1,8 кг расчётных потерь. Чтобы показать отклонение потерь 1,5 кг, увеличить выход мяса до 64,7 кг; остальные выходы сохранить. Завершить.
6. **Заказ 006** (3 минуты). Выбрать вторую охлаждённую тушу УБ-26-000003. Подготовить, запустить, ввести её MTU и 98,8 кг, списать, подтвердить идентификацию полутуш и завершить по плану. Показать отдельный маршрут реализации.
7. **Заказ 007** (7 минут). Показать необязательный резерв и подготовить без него. В «Фаршесоставлении» после запуска последовательно ввести MTU и количества: тримминг 16 кг, шпик 3,6 кг, смесь 0,4 кг. Каждое списание подтвердить отдельно. Завершить по плану, открыть фасовку, запустить и списать MTU упаковки: 50 лотков и 5 коробов. Внутренний фарш 20 кг уже передан из предыдущей операции. Подтвердить проверку упаковки, завершить. **Склады и отгрузки → Готовая продукция → Принять на СГП**, затем отгрузить палету 20 кг получателю.
8. **Заказ 008** (4 минуты). Подготовить без резерва. Запустить приёмку ЦТП, ввести MTU кости из заказа 005 и 13 кг, списать, подтвердить категорию и массу, завершить. Запустить переработку и завершить по плану: 5,3 кг кормовой муки и 3,2 кг технического жира. Остальная масса учитывается как технологические потери.
9. **Учёт и отчёты → Генеалогия партий / Журнал событий**, **Склады и отгрузки → Отгрузки** (5 минут). В реестре генеалогии найти ПЛ-261022-007 и открыть партию. Дерево происхождения содержит всю цепочку заказов 001 → 002 → 005 → 007, исходное хозяйство, тушу УБ-26-000001, фактические MTU и количества. Выбрать заказ в дереве: справа видны состав и выпуск, на вкладке «Операции» доступны результаты. Выбрать партию живка в дереве и нажать «Показать использование»: откроются все фактические ветви, включая тушу на реинспекции и ЦТП. Во вкладке «Использование» у живка реинспекция видна, а в происхождении палеты она отсутствует. Затем в журнале найти списание по MTU и открыть его количество и исполнителя, в отгрузках найти получателя. Завершить обзором выполнения в диспетчерской.

При частичном списании остаток резерва остаётся защищённым. Если фактического сырья меньше плана, заказ не завершится до полного подтверждения потребности. Ещё не подготовленный заказ можно пересчитать по свободным остаткам; уже выполненные операции и фактические выходы при этом не переписываются.

## Генеалогия партий

Вход — реестр партий и продукции с поиском и периодом. Отдельная вкладка содержит производственные заказы. Поиск поддерживает код партии и MTU, ПЗ выпуска, наименование, номер убоя, текущий и исторические RFID разног, хозяйство и ТСДок. Строки выводятся по 25, 50 или 100; возврат к реестру сохраняет запрос, период и страницу. Переход из готовой продукции или отгрузки открывает конкретную партию.

Детальный экран устроен как структура производства в НСИ: дерево связей слева, сведения о выбранном узле справа. «Происхождение» идёт от выбранной партии через заказ выпуска к списанному сырью. «Использование» — через подтверждённых потребителей к следующим партиям и отгрузкам. Партии, заказы и отгрузки различаются иконками. Выбор узла открывает его сведения на той же странице. Состав и выпуск заказа показаны компактными списками; операции вынесены на отдельную вкладку, упаковка, другие выпуски и резервы раскрываются по запросу. Из любого связанного объекта можно открыть самостоятельную цепочку. На узких экранах панели расположены друг под другом с переходами к подробностям и обратно.

Связь строится по фактическим списаниям MTU; резерв не становится доказательством происхождения. При смешении сохраняются обе ветви. Общие предки раскрываются один раз; повторные связи позволяют перейти к первому появлению узла. Количество списания отделено от количества выпуска. Поиск внутри дерева находит код, MTU, наименование, хозяйство, номер убоя или получателя, сохраняя путь к найденному объекту и прежнее состояние сворачивания после очистки. Дерево поддерживает стрелки, Home/End, Enter/пробел для выбора и поиск по первым буквам с клавиатуры.

Партия живка прослеживается на уровне учётной партии: показ её массы не означает, что вся эта масса вошла в выбранную палету. У демо нет индивидуальной идентификации каждой живой свиньи. После убоя сохраняются отдельные партии туш, RFID и номера убоя. Исходное количество при приёмке отделено от текущего остатка; новые приёмки сохраняют исходное количество отдельно. В старых записях оно восстанавливается из остатка и зарегистрированных списаний, для живка — из принятой живой массы.

Большие деревья показываются порциями по 150 узлов с возможностью загрузить следующие; поиск работает по всей цепочке. «Выгрузить связи» экспортирует все фактические списания выбранного исследования и связанные отгрузки, включая скрытые ветви. При печати выводятся сведения выбранного узла и полный перечень связей, выпусков и отгрузок. Отсутствующие источники и циклические связи в повреждённых сохранениях отмечаются явно.

Ориентиры для взаимодействия: [Carbon Tree view](https://www.carbondesignsystem.com/building-blocks/core/components/tree-view/guidelines), [WAI-ARIA Tree View Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/), [Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines), [Carbon Pagination](https://www.carbondesignsystem.com/building-blocks/core/components/pagination/guidelines). Для представления преобразований между входящими и исходящими партиями: [GS1 Global Traceability Standard](https://www.gs1.org/sites/default/files/docs/traceability/GS1_Global_Traceability_Standard_i2.pdf).

## Идентификация туш и скачивание QR

На КТ4 при подтверждённом потреблении живка MES создаёт номер партии убоя по схеме «площадка + год + шестизначный счётчик». Это отдельный номер от идентификатора конкретной туши и кода складской MTU.

Разноги — заранее зарегистрированные многооборотные носители. Кнопка «Считать разногу» имитирует чтение свободной метки из подготовленного набора R-821…R-840; оператор также может ввести известный RFID. Неизвестная или занятая другой тушей разнога отклоняется. КТ8 создаёт постоянную карточку туши, связывает её с партией убоя и разногой. Подтверждение подачи фиксирует списание складской MTU; запуск операции запас не уменьшает.

После получения первичной классификации AutoFom III MES один раз присваивает номер убоя. Формат УБ-ГГ-СССССС — демонстрационная маска, а не заявленный формат промышленного маркировщика. Данные от оборудования в демо явно имитируются; значение постности настраивается в операции НСИ. До ветеринарного контроля необходимо сформировать маркировку, скачать файл и отдельно подтвердить нанесение. Повторное получение данных и повторная печать сохраняют номер и идентичность туши.

«Скачать QR» формирует локально самостоятельный векторный SVG размером 90 × 55 мм с номером убоя, номером партии убоя, датой и QR. QR содержит строку MES:C1:<постоянный идентификатор туши>; временный RFID в него не входит. Печать и подготовка файла — разные учётные события: скачивание не означает физическое нанесение. SVG можно открыть в браузере и распечатать. Задание маркировки содержит тип, адресат AutoMarker-II, идентификатор туши и содержимое QR; фактическая передача команд на промышленное оборудование сейчас не подключена и требует согласования его протокола и формата. QR добавлен для демонстрационного печатного сценария, а не как утверждение о требовании QR в исходном ТЗ.

Номер убоя и QR находят актуальную учётную единицу туши при последующем списании. После охлаждения сохраняется та же идентичность; при разделке либо передаче полутуш разнога освобождается. При смене разноги указываются новая метка и причина, в истории сохраняются обе привязки, исполнитель и время. В генеалогии видны номер убоя, партия убоя, состояние разноги; в карточке индивидуальной партии доступно повторное скачивание QR.

На КТ19 показываются готовые данные: постность AutoFom, учтённая масса туши и ветеринарный допуск с примечаниями. Постность не вводится повторно, а норма 57 % не показывается: это настройка демонстрационного источника, а не норматив качества. При необходимости «Повторное измерение» открывает ввод нового результата и причины; отмена возвращает исходное показание AutoFom. Исходное измерение сохраняется отдельно от повторного. В сокращённом демо масса берётся из подтверждённого учёта туши; отдельный обмен с динамическими весами КТ19 не реализован. Сохраняются масса, постность, источник и результат контроля. Категория присваивается только по настроенным правилам НСИ, сохранённым в снимке процесса. В исходных данных классификатор заказчика отсутствует, поэтому условные категории не присваиваются. Старые результаты и снимки заказов сохраняются; прежние условные категории не выводятся и не используются для новых расчётов. После КТ8 рабочий экран показывает номер туши и RFID, а маркировка, повторное скачивание QR и история разног доступны в разделе «Сведения о туше».

Старые номера, результаты операций, остатки и списания сохраняются. Для ранее учтённых туш восстанавливаются связи по существующим фактам; подтверждение физического нанесения при этом не выдумывается. Если в активном старом заказе номер ещё не был зарегистрирован, новые данные и маркировка подтверждаются текущими отдельными действиями. Завершённые операции не проигрываются повторно. Пользовательские версии процессов не заменяются стандартным маршрутом.
